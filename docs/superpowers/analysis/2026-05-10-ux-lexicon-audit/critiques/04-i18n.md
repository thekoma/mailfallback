# i18n / copy critique

*Voice: bilingual technical writer, ten years shipping Italian B2B SaaS — Aruba, TeamSystem, that flavour. I read the strings as both an Italian and an English speaker would.*

## Bottom line

- **The "backup" overloading is worse in Italian than in English.** "Backup" is a loanword in IT and reads exactly the same — but Italian users have no native word to fall back on for the local mirror. So if MFB picks a single English term for the local copy, IT users will *still* call everything "backup" in conversation, and the docs/UI mismatch will hurt support more than it does in English.
- **MFB's strings today are written in "engineer English" — terse, imperative, sometimes ungrammatical.** Even ignoring the lexicon question, the copy needs a house style. Mixing "Backup now" / "Sync now" / "Start first backup" / "Backed up 5 min ago" in three adjacent surfaces is a tone-of-voice failure independent of which noun wins.
- **The codebase is not i18n-ready.** No `gettext`, no Fluent, no Babel — strings are hardcoded in Jinja2 and Python. Retrofitting is a 2–3 week job done well, and the rename is the right moment to do it (so we don't pay translation cost for strings about to die).

## The bilingual lexicon problem

For each of the five MFB concepts, the Italian and English candidates pull in different directions. The honest table:

### Concept 1 — Source IMAP server (the original mailbox)

| EN candidate | IT candidate | Notes |
|---|---|---|
| Source mailbox | **Casella di origine** | "Origine" is a clean Italian word — feels less technical than "source" |
| Origin account | Account di origine | Mixed register — "account" is English, "origine" is Italian. Italians accept this. |
| Provider | Provider | Same in both. Pulls toward EN. |

**Pull:** Italian wins here. *Casella di origine* is genuinely clearer than "source mailbox", which sounds like a Git concept. **Recommendation:** EN "Source mailbox", IT "Casella di origine". This is one of the few places where Italian copy is *better* than English.

### Concept 2 — Local mirror (the mbsync Maildir)

| EN candidate | IT candidate | Notes |
|---|---|---|
| Local mirror | **Specchio locale** | *Specchio* is metaphorical in IT — sounds poetic, not technical. Risky. |
| Local copy | **Copia locale** | Plain, dull, accurate. Italian users will accept this immediately. |
| Live mirror | Mirror locale | "Mirror" is recognised in IT homelab contexts (ISO mirror, RAID mirror) |
| Working copy | Copia di lavoro | Carries SVN/Git baggage. Avoid. |

**Pull:** English wins. *Mirror locale* (with the loanword) is what Italian sysadmins actually say. *Specchio locale* is what a marketing person would write — and would be wrong. **Recommendation:** EN "Local mirror", IT "Mirror locale". The Italian noun stays English; only the adjective is translated. This is the single most common pattern in Italian sysadmin language.

### Concept 3 — Remote depot (the restic repository)

| EN candidate | IT candidate | Notes |
|---|---|---|
| Backup destination | Destinazione di backup | Current label. Both languages: ambiguous, both inherit the "backup" overloading. |
| Depot | **Deposito** | Maps cleanly. *Deposito* is a real Italian word with the right semantics (a place where you put things for safekeeping). |
| Vault | **Cassaforte** | Too dramatic in IT — sounds like a bank product. Avoid. |
| Repository | Repository | EN loanword; widely understood by technical IT users; opaque to others. |
| Storage location | Posizione di archiviazione | Long, bureaucratic in IT. Avoid. |

**Pull:** Italian gives us a gift here. *Deposito* is the rare case where Italian has a single short native noun that reads cleaner than any English option. **Recommendation:** EN "Depot" (or "Backup depot" if Andrea wants the modifier), IT "Deposito". Both languages benefit from rejecting "destination" entirely.

### Concept 4 — Snapshot (the restic point-in-time)

| EN candidate | IT candidate | Notes |
|---|---|---|
| Snapshot | **Snapshot** | Loanword used unchanged in IT IT/sysadmin contexts (VM snapshots, ZFS snapshots) |
| Snapshot | Istantanea | Native IT translation. Used by Apple Italia ("istantanea dello schermo") but feels consumer-y in technical contexts. |
| Recovery point | Punto di ripristino | Microsoft/Windows convention in IT — recognisable but heavy. |

**Pull:** English wins decisively. Italian sysadmins say "snapshot" without translating. **Recommendation:** EN "Snapshot", IT "Snapshot". Don't translate. If we ever need a verb, it's "creare uno snapshot" — same loanword.

### Concept 5 — Store (the local filesystem path)

| EN candidate | IT candidate | Notes |
|---|---|---|
| Store | Store | EN loanword — opaque in both languages. |
| Volume | Volume | Same in both. Carries Docker/LVM baggage. |
| Mailbox volume | Volume delle caselle | Long, descriptive — works in both. |
| Storage path | Percorso di archiviazione | Bureaucratic IT. |
| Mount | Mount | Sysadmin loanword in both. |

**Pull:** Tied. "Store" is bad in both languages. **Recommendation:** EN "Mailbox volume" (or just "Volume"), IT "Volume" (or "Volume di posta"). The current word is admin-only jargon; let's stop pretending it's a user-facing term.

---

**Summary of the five pulls:** Italian is better for *origine*, *deposito*. English wins for *mirror*, *snapshot*. *Volume* is a draw. **There is no single language that pulls the whole design.** This means MFB needs both languages designed in parallel — not English-first-with-translation-after.

## The case for English-first labels

Even with Italian-speaking users, technical IT teams routinely keep English nouns. Here's where MFB should and shouldn't hold the line.

**Keep in English (don't Italian-ize):**

- *Snapshot* — loanword, universally understood, no Italian equivalent that doesn't sound consumer-y.
- *Restic / mbsync / Dovecot* — proper nouns. Never translate.
- *Log* — Italian sysadmins say "log" not "registro". *"Vedere il log"* is natural; *"vedere il registro"* sounds like Windows Event Viewer in 2003.
- *Cron / scheduler* — same. "Lo scheduler" / "il cron" are loanwords with no friction.
- *Account* — already a loanword. "Account email" reads better than "Casella di posta elettronica" by a wide margin.
- *OAuth / token / API* — universal.
- *Webhook, endpoint, healthcheck* — same.

**Italian-ize:**

- *Source* → *Origine* (or *casella di origine*). "Source" by itself is opaque to a non-English-speaking IT person.
- *Destination* → *Deposito* (when meaning the depot) or *Destinatario* (when meaning the restore target). The word "destination" used unmodified in Italian is jarring.
- *Retention* → *conservazione* (compliance contexts) or *retention* (technical contexts). Giulia (P3) needs *conservazione* for her director slide; Andrea (P1) is fine with either.
- *Schedule* (noun) → *pianificazione* OR *schedule* (verb stays English: *schedulare*). Mix is fine.
- *Settings* → *Impostazioni*. Universal.
- *Failure / Failed* → *Errore / Fallito*. Italian users find untranslated "failed" cold.
- *Save / Cancel / Delete / Edit* → *Salva / Annulla / Elimina / Modifica*. Always translate UI verbs.

**House rule:** translate verbs and consequences (what the user did, what happened); keep nouns referring to *technical artefacts* in English (snapshot, log, repo, mirror, scheduler).

## Voice and tone audit

I sampled 14 strings from `vocab-inventory.md` and categorised each:

| String | Voice | Mood | Register |
|---|---|---|---|
| "Add your first email backup" | Imperative | Direct | Plain |
| "Backed up 5 min ago" | Declarative | Direct | Plain |
| "Start first backup" | Imperative | Direct | Plain |
| "First backup in progress…" | Declarative | Direct | Technical |
| "Backup configuration saved" | Declarative | Direct | Technical |
| "No backup destinations configured yet." | Declarative | Direct | Technical |
| "No backup configured." | Declarative | Direct | Curt |
| "Backup failed" | Declarative | Direct | Curt |
| "Backup failed — unknown error" | Declarative | Direct | Cold |
| "Snapshot restored as 'Backup X (date)'" | Declarative | Direct | Technical |
| "Stores are base directories where mailboxes and Dovecot home directories are saved." | Declarative | Pedagogical | Technical-bordering-on-jargon |
| "This may take a while — first backups download every message in your account." | Declarative | Helpful | Plain |
| "Could not connect to destination server to check folder separator." | Declarative | Diagnostic | Technical |
| "Manage offsite backup destinations for account maildir data." | Declarative | Pedagogical | Mixed jargon |

**Inconsistencies:**

1. **Imperative vs declarative for headings** — admin pages use both ("Add Destination" vs "Backup Destinations"). Pick one (use declarative for section titles, imperative for buttons).
2. **Curt vs helpful for errors** — "Backup failed" gives the user nothing to do; "This may take a while…" is genuinely helpful. The same product can't have both registers without a rule.
3. **Technical leakage in pedagogical strings** — "maildir data" in a helper sentence is jargon a P5 user can't parse.
4. **Punctuation drift** — periods inconsistent (some labels end with ".", some don't); em-dashes vs hyphens used randomly; ellipsis sometimes "…" sometimes "...".
5. **Past-tense success messages don't match async reality** — "Snapshot restored" implies done; the account is actually suspended.

### Proposed 5-rule house style

1. **Buttons are imperative verbs** ("Save", "Delete", "Sync now"). Headings are nouns ("Backups", "Destinations").
2. **Error messages name the system that failed and propose a next action.** No bare "Failed" — always "X failed because Y. Try Z."
3. **No internal jargon in user-facing strings.** "maildir", "Channel", "Far/Near", "expunge" stay in admin disclosures or logs.
4. **Success messages describe state, not action.** "Backup ready" not "Backup completed" if the user can now use it; "Restoring…" if work continues.
5. **Periods on full sentences, none on labels.** "Save" no period. "No snapshots yet." period. Em-dash for parenthetical asides; spaced hyphens forbidden.

## Sentence-level rewrite examples

| # | Before | After | Why |
|---|---|---|---|
| 1 | *No accounts configured yet. Click **New Account** to add your first email backup.* | *No mailboxes connected yet. **Connect your first mailbox** to start backing it up.* | Reframes the primary noun (mailbox not backup), names the action (connect), keeps the second clause for context. |
| 2 | *Start first backup* (button) | *Start first sync* | This action is the local sync, not the offsite backup. The button label was lying. |
| 3 | *Backed up 5 min ago* | *Last synced 5 min ago* | Same correction. The local mirror is up to date — that's a sync timestamp, not a backup. |
| 4 | *Backup failed — unknown error* | *Sync failed. Check the source IMAP credentials, then retry.* OR *Backup to **Depot name** failed. Open the depot to see the restic log.* | Names the system, gives a next action. Two messages because two different failures were sharing a string. |
| 5 | *No backup configured.* | *This mailbox has no offsite backup. **Pick a depot** to start protecting it.* | Disambiguates (offsite, not local), gives the action, links it. |
| 6 | *Manage offsite backup destinations for account maildir data. Each destination is a restic repository backed by S3 or a local path.* | *Depots are where offsite backups live — an S3 bucket or a server path. Each mailbox can be backed up to one depot.* | Drops "destination" and "maildir", explains the relationship in one sentence. |
| 7 | *Snapshot restored as 'Backup gmail-andrea (2026-05-10)'* | *Snapshot restored. The recovered mailbox is **suspended** — review its settings, then **Activate** it to start using it.* | Tells the user the actual state and the next action. The current message lies by omission. |
| 8 | *Stores are base directories where mailboxes and Dovecot home directories are saved.* | *A volume is a disk location where MFB keeps your synced mail. Most installs only need one.* | Removes "Dovecot" (internal), "directories" (technical), explains the user-relevant fact. |
| 9 | *Could not connect to destination server to check folder separator.* | *Can't reach the target IMAP server. The restore needs to log in once to learn the folder layout — check host/port/credentials and try again.* | Names the goal of the connection, gives the diagnostic checklist. |
| 10 | *Backup configuration saved* (flash) | *Offsite backup updated for **Mailbox name**. Next snapshot in **2 h 14 m**.* | Names what changed and what happens next. Current message is vague; the rewrite earns the screen real estate. |
| 11 | *No backup destinations configured yet.* | *No depots yet. **Add a depot** (S3 bucket, SFTP, or local path) before scheduling backups for any mailbox.* | Adds the chronology: depots first, then per-mailbox backup config. Saves the user a wrong-order attempt. |
| 12 | *Backup Destinations* (page title) | *Depots* (page title); subtitle: *Where offsite backups live.* | Loses the "destination" overload. Title is a noun; subtitle teaches in five words. |

## Empty-state and error sentence patterns

Adopting templates removes 80% of the per-string design work. Proposal:

**Pattern A — empty state**

> No `<thing-plural>` yet. **`<primary action verb>`** to `<one-line outcome>`.

Examples:
- *No mailboxes yet. **Connect a mailbox** to start syncing mail.*
- *No depots yet. **Add a depot** to enable offsite backups.*
- *No snapshots yet. The first one will appear after the next scheduled backup (in 4 h).*

**Pattern B — failure**

> `<system>` failed because `<reason>`. `<suggested action>`.

Examples:
- *Sync failed because the IMAP server refused authentication. Check the password, then retry.*
- *Backup to **Depot S3-EU** failed because the bucket is unreachable. Test the depot from the Depots page.*
- *Restore failed because the snapshot is missing files (restic exit 13). Try a different snapshot.*

**Pattern C — inline help (under a form field)**

> `<one short clause about what this affects>`. `<optional default-or-example>`.

Examples:
- *How often this mailbox syncs from the source. Default: every 30 minutes.*
- *Disk path or S3 URL where snapshots will live. Example: `s3:s3.eu-west-1.amazonaws.com/mfb-backups`.*

**Pattern D — confirmation**

> `<primary action>` will `<consequence in present tense>`. `<one-line side effect>`. **Continue?**

Examples:
- *Deleting **gmail-andrea** will remove the local mirror and all sync history. Offsite snapshots are kept. **Continue?***
- *Migrating to **Volume backup-2** will move 12 GB of mail. The account will be unavailable for ~8 minutes. **Continue?***

These four patterns alone would cover roughly 60% of MFB's current strings.

## i18n-readiness assessment

The code today: zero i18n machinery. No `gettext`, no `babel`, no Fluent, no language switcher. Strings are hardcoded in Jinja2 templates, in Python flash messages, and in form labels.

**Effort to make MFB i18n-ready (English + Italian):**

| Step | Effort | Notes |
|---|---|---|
| Add `babel` + Jinja2 `babel` extension | 0.5 d | `pybabel extract`, `pybabel update`, `pybabel compile` workflow. |
| Wrap all template strings in `{% trans %}` / `{{ _("…") }}` | 3–4 d | ~400 strings to wrap (rough count from vocab-inventory). |
| Wrap all Python strings (flash messages, error messages, log messages user-visible) | 1–2 d | ~150 strings. Skip log messages that stay English. |
| Build pluralisation handling | 0.5 d | Italian has different plural rules than English in some edge cases; Babel handles it. |
| Build language detection (Accept-Language header + user setting) | 1 d | Per-user setting in `User` model + middleware. |
| First Italian translation pass | 2–3 d | Native speaker review essential. Andrea can do it. |
| QA pass — context strings (where the same word means different things) | 1 d | Babel's `pgettext` for disambiguation. |
| Documentation site i18n | 2 d | mkdocs-material has built-in i18n via `mkdocs-static-i18n`. |
| **Total** | **11–14 days** | One sprint, plus translation effort. |

**Sequencing recommendation:** do the rename *first* (Phase 5–8 of this audit), let the new lexicon settle for one release cycle, *then* add i18n. Translating strings about to be renamed is wasted effort; translating new strings as they're written is cheap.

**One thing to prepare now:** when writing the new English strings (Phase 5 lexicon), avoid English-isms that don't translate — idioms ("set and forget", "good to go", "you're all set"), contractions in formal contexts, and phrasal verbs that need a paragraph in Italian. The mockups should be writable in Italian without rewriting.

## Things the current-state doc gets wrong from copy angle

1. **It treats the lexicon as a noun problem, but the bigger problem is verb consistency.** "Sync now" / "Backup now" / "Start first backup" / "Run sync" — four buttons for the same action. Even if every noun was perfect, the verbs would still confuse. The lexicon proposal in Phase 5 must include a verb table, not just nouns.

2. **It scores "Snapshot, Store, Maildir" as clean, but two of those (Store, Maildir) are clean *only because nobody outside admin sees them*.** That's not lexicon hygiene, that's hiding the problem. The moment "Store" appears in a user-facing flow (the migration UI does, today), it becomes confusing. The current-state doc undercounts the surface.

3. **It frames the rename as a Phase 5 deliverable, but the **copy quality** problem (tone, voice, sentence patterns) is independent of which nouns win.** Even if MFB kept the word "backup" everywhere, the strings need rewriting. The audit should split these into two parallel tracks: lexicon (nouns) and copy (everything else). Otherwise the rename ships with the same curt, inconsistent voice, just with new words.
